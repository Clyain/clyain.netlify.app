Scratch 文件格式

Scratch 3.0 文件格式 是用于存储导出的 Scratch 3.0 项目和角色的格式。 这些文件是 ZIP 压缩包，其中包含以 JSON 文本格式编码的信息，以及单独存储的项目媒体文件。 项目文件的扩展名为 .sb3，角色文件的扩展名为 .sprite3。

1. 项目文件

一个 .sb3 文件是一个 ZIP 压缩包，包含一个名为 project.json 的 JSON 文件，该文件表示整个项目。（在大多数操作系统上，可以通过先将文件重命名为以 .zip 结尾来解压 .sb3 文件，或使用 7-Zip 等程序直接右键打开。）背景、造型和声音以单独的文件存储，文件名以它们的 MD5 校验和开头，后跟文件扩展名。

2. 角色文件

.sprite3 文件与项目文件类似，但其中的 JSON 文件名为 sprite.json，并将角色表示为一个目标 (target)。

3. 格式

3.1 项目

项目具有以下属性：

targets（目标）
数组，顺序与 Scratch 用户界面中的顺序相同。
monitors（监视器）
数组，按它们的图层顺序排列。
extensions（所使用的扩展标识）
数组。
内置拓展以及它们对应的标识：[1]
  • pen：画笔
  • wedo2：LEGO Education WeDo 2.0
  • music：音乐
  • microbit：micro:bit
  • text2speech：文字朗读
  • translate：翻译
  • videoSensing：视频侦测
  • ev3：LEGO MINDSTORMS EV3
  • makeymakey：Makey Makey
  • boost：LEGO BOOST
  • gdxfor：Go Direct Force & Acceleration
meta
关于项目作者和所用 Scratch 版本的元数据。

3.2 目标 (Targets)

目标 是指舞台或角色。
所有目标具有以下属性：[2]

isStage
如果是舞台则为 true，否则为 false。默认为 false。
name
角色的名称。舞台始终为 "Stage"。如果未提供，目标将无法加载。
variables
一个对象，将 ID 与表示变量的数组关联。数组的第一个元素是变量名，第二个是值，第三个元素为 true 表示该变量是云变量，否则不存在。
lists
一个对象，将 ID 与表示列表的数组关联。数组的第一个元素是列表名，第二个是列表数组。
broadcasts
一个对象，将 ID 与广播名称关联。通常仅存在于舞台中。
blocks
一个对象，将 ID 与积木关联。
comments
一个对象，将 ID 与注释关联。
currentCostume
一个数值，记录着项目被保存时的造型编号。
costumes
数组，存储这个对象的造型。
sounds
数组，存储这个对象的声音。
layerOrder
一个数值，记录着项目被保存时的图层编号。
volume
一个数值，记录着项目被保存时这个对象的音量。

3.3 积木 (Blocks)

opcode（操作码）
一个字符串，用于命名该积木。积木操作码列表可在此处查看。
next
下一个积木的 ID，若无则为 null。
parent
若该积木是栈积木且前面有其他积木，则此属性为前一个积木的 ID。
若该积木是 C 型积木中的第一个栈积木，则此属性为 C 型积木的 ID。
若该积木是另一个积木的输入，则此属性为那个积木的 ID。
其他情况下则为 null。
inputs
一个对象，将名称与这块积木中的输入的数组关联，这些数组表示可拖入其他积木的输入槽，包括 C 型积木的输入口。
fields
一个对象，将名称与数组关联，这些数组表示字段。每个数组的第一个元素为字段的值。对于某些字段，如变量下拉菜单和广播消息下拉菜单，还存在第二个元素，即该字段值的 ID。[3]
shadow
如果该积木是阴影块则为 true，否则为 false。
topLevel
如果该积木没有父级积木则为 true，否则为 false。

一个顶层积木对象还包含 x 和 y 属性，表示该积木在代码区域中的坐标。
若积木附有注释，则还有一个 comment属性，其值为该注释的 ID。
若积木带有变体 (mutation)，则还有一个 mutation属性，其值为表示该变体的对象。

少数积木以数组形式表示，其第一个元素为表示所应用积木的数字。[4][5] 但这些积木也可以使用常规格式表示，正如在背包中所做的那样。[6] 不过，在调用使用时，Scratch 会自动将这些积木转换为数组格式。


3.3.1 输入 (Inputs)

在输入这个对象中，会有一个或多个键值对。
如 在(1)秒内滑行到(随机位置 v) 它的积木代码大概是这样子的： 
"a": {
    "opcode": "motion_glideto",
    "next": null,
    "parent": null,
    "inputs": {
        "SECS": [
            1,
            [
                4,
                "1"
            ]
        ],
        "TO": [
            1,
            "b"
        ]
    },
    "fields": {},
    "shadow": false,
    "topLevel": true,
    "x": 48,
    "y": 704
},
"b": {
    "opcode": "motion_glideto_menu",
    "next": null,
    "parent": "a",
    "inputs": {},
    "fields": {
        "TO": [
            "_random_",
            null
        ]
    },
    "shadow": true,
    "topLevel": false
}
在主积木块中（motion_glideto），inputs 中的 SECS 和 TO 分别表示两个输入槽。

"SECS": [
    1,
    [
        4,
        "1"
    ]
],
在其中，如果第一个元素为
1表示该输入为阴影块（即这里是可以输入的，你可以把任何一个报告块放在里面），
2 表示没有阴影块（这种情况比较少见，这里会显示为一个比较宽的深色胶囊型，你不能更改文本，只能往里面填充积木），
3 表示存在阴影块但被输入遮盖（这种情况就是当你报告块放在里面的时候）。[7]

第二个元素为输入积木的 ID，或表示该输入积木的数组（具体格式见下表）。
积木类型 第 1 个元素 第 2 个元素 第 3 个元素 第 4 个元素 第 5 个元素
数字 4 值
正数 5 值
正整数 6 值
整数 7 值
角度 8 值
颜色 9 "#" 后跟十六进制颜色值
字符串 10 值
广播 11 名称 ID
变量 12 名称 ID x 坐标（若顶层） y 坐标（若顶层）
列表 13 名称 ID x 坐标（若顶层） y 坐标（若顶层）

若存在被遮盖的阴影块，则第三个元素为该阴影块的 ID 或表示该阴影块的数组。[8]

就如在(secs)秒内滑行到(随机位置 v)，此时里面就变成了"SECS":[3,[12,"secs","`jEk@4|i[#Fk?(8x)AV.-my variable"],[4,"1"]]，
"SECS"的第一个元素是3，表示存在阴影块但被输入遮盖，
第二个元素是[12,"secs","`jEk@4|i[#Fk?(8x)AV.-my variable"]，表示阴影块上方的积木名称为"secs"的一个变量（12），
第三个元素是[4,"1"]，表示阴影块的类型为数字，值为"1"。

3.3.2 字段 (Fields)

一般是指文本框、不接受子积木的下拉菜单（长得像方形的下拉菜单框）等，比较特殊的还有音乐拓展中那些点击就可以弹出音符键盘的输入框（NOTE）和比较少见的矩阵（MATRIX）。这些元素直接用于那些无法拖入报告块的输入型积木中。然而，大多数情况下，用户应当能够拖入报告块；此时积木中并不直接存在字段，而是存在一个输入槽，且该输入槽中可能包含一个阴影块。


3.3.3 阴影块 (Shadow blocks)

是指位于输入槽中的一种报告块，用户可以在其中输入或选择值。它无法被拖拽移动，但可以被普通的报告块替换。[9] Scratch 内部将这些也视为积木，尽管通常并不被当作积木看待。（这些概念来源于 Blockly，Scratch 积木系统正是基于 Blockly 开发的。）


3.3.4 变体 (Mutations)

变体存在于 opcode 属性为 "procedures_call"（即自定义积木调用）、"procedures_prototype"（即自定义积木定义内部）或 "control_stop" 的积木上。变体具有以下属性：

tagName
始终等于 "mutation"。
children
似乎始终为空数组。

"procedures_prototype" 和 "procedures_call" 的变体还具有以下附加属性：

proccode
自定义积木的名称，包含输入占位符：%s 表示字符串/数字输入，%b 表示布尔输入。
argumentids
参数 ID 的数组；这些也可以在主积木的 input 属性中找到。
warp
是否以“运行时不刷新屏幕”方式运行该积木。

"procedures_prototype" 的变体还具有以下附加属性：

argumentnames
参数名称的数组。
argumentdefaults
参数的默认值数组；对于字符串/数字参数，此为空字符串；对于布尔参数，为 false。

"control_stop" 的变体还具有以下附加属性：

hasnext
该积木后面是否还有其他积木（stop all 和 stop all in sprite 为 false，stop other scripts in sprite 为 true）。

3.4 注释 (Comments)

注释具有以下属性：

blockId
该注释所附加到的积木的 ID。
x
注释在代码区域中的 x 坐标。
y
注释在代码区域中的 y 坐标。
width
宽度。
height
高度。
minimized
如果注释已折叠则为 true，否则为 false。
text
注释文本。

3.5 资源 (Assets)

资源 是指造型或声音。（背景也被视为造型。）它们具有以下属性：[10]

assetId
资源文件内容的 MD5 哈希值。
name
资源的名称。
md5ext
资源文件的名称；基本上就是 assetId 加上相应的文件扩展名。
dataFormat
资源文件格式的名称。

3.5.1 造型 (Costumes)

造型除了所有资源共有的属性外，还具有以下属性：

bitmapResolution
位图造型缩放因子的倒数。可能不存在。在 Scratch 3.0 中，所有位图造型都是双倍分辨率。[11]
rotationCenterX
旋转中心的 x 坐标。
rotationCenterY
旋转中心的 y 坐标。

3.5.2 声音 (Sounds)

声音除了所有资源共有的属性外，还具有以下属性：

rate
声音的采样率（赫兹）。
sampleCount
样本数。

这些附加属性在加载声音时会被忽略并覆盖[12]，因此可以完全省略。


3.6 监视器 (Monitors)

监视器具有以下属性：

id
ID。
mode
监视器的模式名称："default"、"large"、"slider" 或 "list"。
opcode
该监视器所属积木的操作码。
params
一个对象，将监视器所属积木的输入名称与其值关联。
spriteName
监视器所属目标的名称（如果有）。
value
监视器上显示的值。
width
宽度。
height
高度。
x
x 坐标。
y
y 坐标。
visible
如果监视器可见则为 true，否则为 false。

不属于列表的监视器还具有以下属性：

sliderMin
监视器滑块的最小值。
sliderMax
监视器滑块的最大值。
isDiscrete
如果监视器的滑块只允许整数值则为 true，否则为 false。

3.7 元数据 (Metadata)

项目 JSON 文件的 meta 属性具有以下属性：

semver
始终为 3.0.0。
vm
创建该项目时所使用的 Scratch VM 版本。
agent
最后编辑该项目之人的用户代理字符串。
